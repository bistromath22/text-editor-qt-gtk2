## 7. DOCUMENT MODEL AND PLAIN-TEXT RULES

Maintain one authoritative plain-text document model.

Use `GtkTextBuffer`.

The document must contain ordinary UTF-8 text only.

Do not use:
- HTML.
- Rich-text serialization.
- Embedded images.
- Child widgets.
- Paintables.
- Document objects.

GtkTextTags may be used internally for visual presentation, such as line height and current-line highlighting.

These tags must never appear in saved files.

### Newline policy

Use LF (`\n`) as the canonical internal newline representation.

At every external input boundary:

1. Convert CRLF (`\r\n`) to LF first.
2. Convert remaining CR (`\r`) to LF.
3. Preserve existing LF.

Do not accidentally convert CRLF into two newlines.

### Important GTK4 buffer behaviour

GTK text buffers represent logical lines with line separators between lines. The last logical line has no trailing line separator.

Account for this when loading, exporting, copying, and testing text.

Do not blindly append an extra newline when saving.

The exported text must accurately preserve whether the input contained a trailing newline.

For example:

```text
hello
world
```

and:

```text
hello
world

```

must remain different documents.

Preserve:
- Leading newlines.
- Trailing newlines.
- Consecutive empty paragraphs.
- Empty files.
- Multiple blank lines.

A visual line wrap must never introduce a stored newline.

### UTF-8 policy

Use valid UTF-8 internally.

On file load:

- Validate UTF-8.
- Detect and strip a UTF-8 BOM if present.
- Normalize external line endings.
- Reject invalid UTF-8 with a clear error rather than silently corrupting data.

On save:

- Export plain UTF-8.
- Use LF output line endings.
- Do not write styling information.

Document this policy.

### Round-trip invariant

For supported UTF-8 text, loading a file and then saving without editing must preserve its logical text content, subject only to the documented BOM removal and newline normalization policy.

## 8. ENTER, PASTE, COPY, CUT, UNDO, AND REDO

This is one of the highest-priority areas of the application.

Manual typing and clipboard operations must behave consistently.

### A. Enter/Return

Use GTK4's native GtkTextView editing behaviour where possible.

Pressing Enter must insert exactly one logical paragraph break.

Support:
- Enter in a non-empty line.
- Enter in an empty line.
- Repeated Enter.
- Enter at the beginning of a line.
- Enter at the end of a line.
- Enter while a selection is active.
- Enter adjacent to existing blank lines.

Do not turn a logical newline into a visual wrap.

Do not unnecessarily intercept GTK's normal keyboard input handling.

Ensure that configured paragraph presentation remains consistent after pressing Enter.

### B. Paste

Implement deliberate plain-text clipboard insertion.

An acceptable implementation is to intercept the `GtkTextView::paste-clipboard` signal and route it through a custom asynchronous GDK clipboard operation.

Use:

- `gdk_clipboard_read_text_async()`
- `gdk_clipboard_read_text_finish()`

Do not depend blindly on GTK's default paste implementation if it bypasses the application's newline-normalization policy.

Paste behaviour:

1. Read the clipboard as plain text.
2. Ignore rich-text formatting.
3. Normalize CRLF and CR to LF.
4. Replace the active selection, if present.
5. Insert at the correct cursor position.
6. Preserve all intentional newlines.
7. Preserve leading and trailing blank lines.
8. Place the cursor at the end of the inserted text.
9. Update current-line highlighting.
10. Update line numbers.
11. Update the status row.
12. Keep scrolling and cursor visibility correct.
13. Mark the document modified.
14. Group the entire paste into one undoable operation.

Because clipboard reading is asynchronous, preserve the paste insertion location correctly.

Use temporary GtkTextMarks to retain the intended insertion and selection boundaries while clipboard data is being retrieved, or otherwise prevent intervening editing from making the insertion location ambiguous.

Ensure temporary marks are deleted when the operation completes or fails.

The paste operation must use:

`gtk_text_buffer_begin_user_action()`

and:

`gtk_text_buffer_end_user_action()`

as appropriate.

A complete multiline paste must be one logical undo operation.

For non-text clipboard formats, safely ignore the unsupported content.

Do not insert images, paintables, or child widgets.

### C. Copy

Copy must export the selected text as plain UTF-8.

Use `GdkClipboard` and `gdk_clipboard_set_text()`.

Do not export:
- Editor colours.
- Font attributes.
- Paragraph styling.
- HTML.
- Images.
- Embedded objects.

Preserve paragraph breaks.

### D. Cut

Cut must:

1. Extract the selected text.
2. Set the clipboard to plain text.
3. Remove the selection.
4. Group the deletion into one user-visible undo operation.

### E. Undo and redo

Enable native GTK4 text-buffer undo.

The Edit menu must provide Undo and Redo.

The menu actions should reflect the availability of undo/redo.

A multiline paste must undo in one action.

Repeated Enter operations must undo correctly.

Cut must undo correctly.

Redo must restore the exact document text.

Loading a file must establish a clean undo/modified-state baseline.

Changing visual settings must not create text-editing undo actions.

Applying tags, changing colours, changing fonts, and changing layout must not mark an otherwise clean document as modified.

Do not create a separate C undo engine unless GTK4 cannot provide the required contract.

- Existing document text.


- NaN.

## 19. KNOWN GTK4 IMPLEMENTATION RISKS THAT MUST NOT BE REPEATED

Pay particular attention to the following issues.

1. Do not confuse GtkTextView visual line wrapping with logical newline characters.

2. Do not export GTK text tags, CSS formatting, or other presentation details into the saved file.

3. Do not blindly use GTK's default clipboard paste if it does not satisfy the explicit plain-text and newline-normalization requirements.

4. Do not make multiline paste multiple separate undo operations.

5. Do not modify document text while applying current-line highlighting.

6. Do not assume UTF-8 byte offsets and GtkTextIter character offsets are interchangeable.

7. Do not calculate line-number Y coordinates by multiplying line numbers by an assumed fixed height.

8. Do not build a separate scrolling gutter that can drift from the text view.

9. Prefer GtkTextView's gutter API over unnecessary custom scrolling implementations.

10. Do not let the CSS provider override the configured editor border colour.

11. Do not confuse the editor's border with the native Ubuntu window frame.

12. Do not implement border thickness by adding an arbitrary spacer widget.

13. Do not treat the status row as editor bottom padding.

14. Do not introduce GTK3-only rendering approaches into GTK4.

15. Do not use unsupported custom drawing methods or suppress invalid rendering warnings.

16. Do not use fixed line heights that clip Unicode or fallback fonts.

17. Do not reapply formatting to the entire document on every individual keypress unless profiling demonstrates that it is necessary.

18. Do not allow configuration reload to create text changes or invalidate the undo stack.

19. Do not duplicate configuration defaults in multiple source files.

20. Do not pretend multiple files are open when only one GtkTextBuffer is active.

21. Do not change the current filename before a successful Save As operation.

22. Do not mark a document clean following a failed save.

23. Do not lose the active document after cancelling a file dialog or an unsaved-changes prompt.

24. Do not introduce unnecessary third-party dependencies.

25. Do not claim that an untested build or test suite has passed.
