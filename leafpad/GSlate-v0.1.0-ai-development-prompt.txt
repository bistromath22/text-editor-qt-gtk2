The current source contains the following implementation elements.

APPLICATION AND UI
------------------

- Native GTK 2 GtkWindow.
- Initial window size approximately 900 x 600.
- Minimum requested size approximately 400 x 300.
- Traditional File, Edit and View menus.
- One GtkTextView backed by one authoritative GtkTextBuffer.
- GtkScrolledWindow around the editor.
- Optional GtkDrawingArea line-number gutter.
- Optional status label showing logical line and column.
- Full-screen toggle.
- A dark default editor palette.
- Desktop entry and an SVG icon.

FILE AND DOCUMENT BEHAVIOR
--------------------------

- New, Open, Save, Save As and Quit actions.
- Save/discard/cancel confirmation for unsaved changes.
- UTF-8 validation during file loading.
- UTF-8 plain-text saves.
- LF as the normalized internal and saved newline representation.
- CRLF is converted to one LF; remaining CR is converted to LF.
- Leading, trailing and repeated logical newlines are preserved by the
  normalization helper.
- File writing uses GLib's g_file_set_contents_full() with consistent and
  durable flags and an explicit GFileSetContentsFlags conversion.
- Saving does not serialize GtkTextTags or editor presentation metadata.
- Only one document is supported. If several paths are supplied, the
  first one is opened and additional paths are reported as unsupported.

EDITING
-------

- Typing and normal GtkTextView editing.
- Copy and cut through GTK text-buffer clipboard functions.
- Explicit plain-text paste through gtk_clipboard_wait_for_text().
- Pasted CRLF/CR line endings are normalized to LF.
- Paste replaces the selection, inserts at the cursor and is grouped as
  one compound undo action.
- Non-text clipboard content is reported as unsupported.
- Snapshot-based UndoManager connected to GtkTextBuffer signals.
- Undo history has a fixed maximum of 500 stored snapshots.
- Modified state compares the current buffer text with the saved text.

SEARCH AND NAVIGATION
---------------------

- Find dialog.
- Find Next.
- Search wraps to the start of the document when no later match exists.
- Go to Line accepts a 1-based logical line number.
- Word wrap toggle.
- Font increase and decrease actions; supported font-size range is 6–96.

VISUAL FEATURES
---------------

- Configurable editor background and text colour.
- Configurable font family and font size.
- Configurable tab width using Pango tab stops and approximate font metrics.
- Configurable paragraph pixels above, below and inside wrapped lines.
- Optional logical line-number gutter.
- Gutter width is calculated from the number of decimal digits needed for
  the current logical line count; it is not intended to count visual wraps.
- Optional current-line paragraph background tag.
- Configurable editor surround colour and size.
- Optional preliminary custom block-cursor rectangle.
- Optional status bar.
- Runtime configuration reload.

CONFIGURATION AND CLI
--------------------

- GLib GKeyFile INI configuration.
- One EditorConfig defaults structure is used as the canonical default
  source and by the default-config serializer.
- Partial configuration files can override supplied keys.
- Common scalar and colour values have basic validation and warnings.
- Keyboard accelerator parsing and runtime reinstallation are present.
- Duplicate shortcuts are detected and ignored where the current parser
  recognizes the conflict.
- Command-line options include --config, --print-config,
  --print-config-paths and --version.
- GLib option parsing supplies --help.

BUILD AND TEST

- C++17 required; compiler extensions disabled.
- GTK 2 target found through pkg_check_modules(GTK2 REQUIRED IMPORTED_TARGET

9. BLOCK CURSOR — CURRENT IMPLEMENTATION AND REQUIRED REFINEMENT
======================================================================

The current implementation is preliminary, not a finished terminal
cursor. It currently:

- hides GtkTextView's normal insertion cursor when block mode is enabled;
- obtains insertion iterator geometry from GtkTextView;
- converts buffer coordinates into widget coordinates;
- obtains approximate character width from Pango font metrics;
- draws a translucent rectangle after the text view's expose event;
- redraws on insertion-mark movement and vertical adjustment changes.

It does NOT yet reliably invert or redraw the character underneath the
cursor. It uses approximate average character width. Do not describe it
as a fully accurate terminal-style block cursor until improved and tested.

The desired behavior:

1. Normal GTK insertion cursor remains the default.
2. block_cursor=true enables block mode; false restores the normal caret.
3. Ctrl+B toggles the mode while running.
4. Draw a clearly visible, preferably opaque block at the actual
   insertion position.
5. Where technically feasible, render the character under the cursor in
   a contrasting foreground colour against the block background.
6. Use actual GTK 2 iterator/layout geometry, not guessed absolute
   screen coordinates.
7. Derive dimensions from the glyph/layout at the cursor where possible.
8. Handle ordinary monospace text, proportional fonts, tabs, end-of-line,
   empty lines, selections, wide Unicode, combining marks, emoji and
   fallback fonts as safely as possible.
9. Update correctly on cursor movement, typing, deletion, paste, undo,
   redo, scrolling, horizontal scrolling, resizing, font changes,
   configuration reload and word-wrap changes.
10. Do not let the cursor drawing alter buffer contents, selection,
    cursor position, modified state or undo history.
11. Do not draw the block in unrelated GTK widgets.
12. Preserve keyboard editing and selection behavior.
13. Avoid flicker, stale cursor rectangles and drawing outside the text
    view's visible region.
14. Use GTK 2 expose-event/drawing facilities; do not use GtkOverlay or
    GTK 3/4 draw callbacks.

Investigate whether the actual glyph can be repainted reliably using the
available GTK 2/Pango layout. If exact glyph inversion is not robust for
all glyph clusters, implement the most reliable documented fallback and
state its limits. Do not pretend that an approximate average-width block
is exact for emoji, combining marks or proportional fonts.

Add a clear config comment documenting cursor_color semantics. Define
whether cursor_color is the block background, the contrasting glyph
foreground, or a legacy cursor tint. Do not silently assign conflicting
meanings to the same setting. Add a separate key if two independent
colours are needed, and update canonical defaults, parser, serializer,
example config and tests consistently.

13. UNDO / REDO
======================================================================

The current UndoManager stores complete before/after text snapshots. It
is not based on a GTK 2 built-in undo API. It listens to GtkTextBuffer
changed and user-action signals and groups compound paste operations.
The current history limit is 500 snapshots.

Known limitations:

- Snapshot storage can consume substantial memory for large documents.
- Cursor and selection positions are not comprehensively restored.
- Dedicated automated undo/redo tests are not yet present.

Preserve reliable text restoration while improving these limitations.
At minimum:

1. Undo and redo restore exact buffer text.
2. Multiline paste remains one logical undo step.
3. Cut and selected-text replacement are undoable.
4. Resetting after New/Open clears the previous document history.
5. Saving marks the exact current text clean.
6. Undoing back to saved text restores the clean title state.
7. New edits after undo clear the redo branch.
8. Visual-only changes never create document history.
9. Signal callbacks remain valid and are disconnected safely.
10. Cursor and selection restoration should be improved and tested.

If replacing snapshots with an operation-based undo system, do so only
with a complete test strategy. Do not introduce fragile complexity merely
for theoretical optimization.
