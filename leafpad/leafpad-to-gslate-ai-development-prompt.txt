Add a clearly visible configurable surround around the editor area.

D. Line-number gutter

Requirements:

- Correct response to scrolling, resizing, font changes, wrap changes,

- Gutter width should adapt to line-count digit count and font metrics.
- Gutter colours configurable.
- No second independent vertical scrollbar.
- Efficient redraw; avoid redrawing the whole document unnecessarily.

Use GtkTextView coordinate and visible-rectangle APIs supported by GTK 2.
Do not estimate line positions using a guessed fixed line height.

E. Current-line highlighting

Add an optional highlight for the logical paragraph containing the insertion

Requirements:

- Configurable colour and visibility.
- Update on cursor movement and relevant buffer changes.
- Correct behaviour with selections, blank lines, wrapped lines, scrolling,
  document load, undo and redo.
- It must not change saved text, modified state or undo history.
- It must not move the cursor or disturb selection.
- Avoid flicker and unnecessary full-buffer tag updates.

Use a GtkTextTag or GTK 2 drawing approach that is proven to work with the

    pixels_below=0

6. CRITICAL FEATURE: STEADY NON-BLINKING BLOCK CURSOR
======================================================================

This is a high-priority feature and must be implemented carefully.

Add an optional terminal-style block cursor for the GtkTextView insertion
point. When block-cursor mode is enabled, the block must remain continuously
visible. It must NOT blink, pulse, flash, periodically disappear, or inherit
the GTK theme's cursor blink timing.

Default:

    block_cursor=false

When enabled:

- Hide the normal thin insertion cursor in the editor only.
- Draw a solid block at the actual insertion cursor location.
- Keep the block continuously visible for as long as the editor is active,
  including when the user is idle.
- Do not use a timer to blink it.
- Do not periodically toggle visibility.
- Do not rely on gtk-cursor-blink being false globally as the sole solution.
- Do not change cursor behaviour in menus, dialogs or other GTK widgets.
- Keep normal selection rendering and text editing intact.
- The block should approximate one character cell at the insertion point.
- Determine its geometry from GtkTextView layout coordinates and Pango
  metrics, not guessed x/y positions or a hard-coded character width.
- Render the glyph underneath in a contrasting foreground where practical,
  so the character remains legible.
- Handle insertion at end-of-line, empty lines, end-of-buffer, tabs, Unicode,
  combining marks, fallback glyphs, variable-width text and wrapped lines.
- Update correctly after typing, deletion, cursor movement, selection changes,
  scrolling, vertical/horizontal adjustment changes, expose/redraw, window
  resize, font change, line-height change, wrap change, configuration reload
  and focus transitions.
- Do not leave stale block fragments after the cursor moves.
- Do not draw the block over the wrong visual row when text wraps.
- Do not let the block cursor interfere with drag selection or mouse placement.

GTK 2 implementation guidance:

1. Inspect the exact GtkTextView event/expose lifecycle available in the
   project's GTK 2 target.
2. Use GTK 2-compatible expose-event drawing and/or a carefully integrated
   child drawing component. Do not use GtkOverlay or GTK 3 draw callbacks.
3. Obtain the insertion GtkTextIter from the GtkTextBuffer insertion mark.
4. Use gtk_text_view_get_iter_location() and
   gtk_text_view_buffer_to_window_coords() or the appropriate GTK 2 APIs to
   derive the cursor rectangle in the correct text window.
5. Determine character-cell width from actual Pango layout/font metrics and
   the character at the insertion position. Do not assume all glyphs are
   one monospace cell; tabs and wide Unicode glyphs need special handling.
6. At end-of-line or end-of-buffer, derive a sensible cell width from the
   active font metrics.
7. Draw a solid rectangle using Cairo/GDK facilities available in the
   installed GTK 2 version.
8. Draw the underlying glyph in a contrasting colour when it exists and
   doing so is correct for the actual text layout.
9. Queue redraws only for the old and new cursor areas when possible.
10. Ensure expose redraws restore the block reliably without flicker.

The standard GtkTextView insertion cursor may blink internally. When block
mode is active, suppress or hide that thin cursor only for this editor widget
using a GTK 2-supported, scoped mechanism. Verify the result under GTK themes
with cursor blinking enabled. The custom block itself must be drawn on every
necessary expose and remain steady even if the desktop setting requests
blinking.

When block mode is disabled, restore the ordinary GTK insertion cursor and
its normal theme-controlled behaviour exactly as before.

Do not globally alter GtkSettings cursor blink properties for the entire
desktop session. Do not make the block cursor disappear when focus is lost
unless that is a deliberate, documented focus policy; preferably distinguish
focused and unfocused states subtly while keeping the cursor solid when the
editor has focus.

Add a manual test specifically to leave the editor idle for at least 60 seconds
and verify that the block cursor never blinks or disappears. Also test repeated
typing, movement, scrolling, resizing, tabs, empty lines and Unicode.

If GTK 2 cannot reliably support a particular case, isolate the limitation,
explain it and provide the most reliable implementation possible. Do not claim
success without visual verification.
