# AI DEVELOPMENT PROMPT
# Transform Leafpad source into a modern, config-driven plain-text editor
# with dark theme, non-blinking block cursor, and features matching config.ini
# (inspired by the gSlate Editor design goals)

---

## 1. ROLE AND OVERALL OBJECTIVE

Act as a senior C language and GTK desktop-application architect and developer.

You are given the complete source tree of **Leafpad** (a classic lightweight GTK text editor written in C).

Your task is to produce a **new, maintainable C application** derived from the Leafpad codebase that implements the visual identity, configuration system, editing behaviour, and keyboard-driven features described in the supplied `config.ini` and the design goals below.

The resulting application shall be named:

**gSlate Editor** (binary name: `gslate`)

Primary goals:
- Keep the small, focused, lightweight spirit of Leafpad.
- Add a human-readable INI configuration system driven by the supplied `config.ini` style.
- Implement a dark, low-distraction colour scheme.
- Provide a **non-blinking block cursor**.
- Support the editor appearance, spacing, line-number, current-line, and status-bar options from the configuration.
- Provide the keyboard shortcuts listed in the configuration.
- Remain a pure C application (C17 preferred) that builds with Meson + Ninja on Ubuntu 26.04.
- Prefer GTK4 where practical. If a full GTK2 → GTK4 port is too large for a single pass, produce a clean GTK3 intermediate that already contains the new configuration system, block cursor, and visual features, and clearly document the remaining GTK4 migration steps.

Do **not**:
- Turn it into an IDE, multi-document editor, or Electron/Qt application.
- Add syntax highlighting, plugins, tabs, or project management.
- Leave core features as TODOs or stubs.
- Break the existing Leafpad file-open / save / undo behaviour without replacing it with an equivalent or better implementation.

The deliverable must be a complete, compilable source tree with build instructions, example configuration, desktop file, and a short design document explaining the changes made to the original Leafpad architecture.

## 5. CORE FEATURES THAT MUST BE IMPLEMENTED

### 5.1 Configuration system

- Use GLib `GKeyFile`.
- Discovery order:
  1. `./config.ini` (current working directory)
  2. `$XDG_CONFIG_HOME/gslate-editor/config.ini` (usually `~/.config/gslate-editor/config.ini`)
  3. `/etc/gslate-editor/config.ini`
  4. Built-in canonical defaults
- Support `--config PATH` on the command line.
- Support `--print-config` and `--print-config-paths`.
- Live reload (Ctrl+R / menu) that updates fonts, colours, border, line numbers, status bar, word wrap, and accelerators **without** changing document content, undo history, or modified state.
- Validate colours, sizes, and accelerators; fall back to defaults with a clear warning on invalid values.

### 5.2 Non-blinking block cursor (highest visual priority)

- Implement a **block cursor** that does **not** blink.
- The cursor should be a solid rectangle covering the character cell (or approximate width of one character).
- Colour should be derived from the text colour or a configurable cursor colour (default to a high-contrast colour such as the text colour inverted or a distinct accent).
- The block cursor must:
  - Stay correctly positioned while typing, selecting, scrolling, and resizing.
  - Survive font size changes and line-height changes.
  - Not interfere with input methods / pre-edit text.
  - Not force overwrite mode unless the user explicitly wants it.
- If a perfect overlay is difficult on the chosen GTK version, document the limitation and provide the best reliable approximation (e.g. a custom drawing overlay on the text view or a carefully managed GtkTextTag + caret).

### 5.3 Visual appearance

- Dark background (`#1e1e2e`) and matching gutter / border / current-line colours.
- Configurable border around the editor area (use a `GtkFrame` or equivalent container + CSS class). The border must **not** affect the native window decorations.
- Optional logical line-number gutter (prefer GTK text-view gutter API when on GTK3/4).
- Optional current-line highlighting (paragraph background).
- Optional status bar showing `Ln X, Col Y` (1-based).
- Configurable monospace font and size.
- Proportional line-height support (`line_height = 1.4`).

### 5.4 Editing behaviour

- One document at a time (preserve Leafpad’s single-window model).
- Reliable UTF-8 loading/saving with BOM stripping and CRLF/CR → LF normalisation (preserve trailing newlines correctly).
- Native or carefully implemented undo/redo that treats a multi-line paste as a single undo step.
- Explicit plain-text clipboard handling (no rich-text leakage).
- Word-wrap toggle.
- Find / Find Next and Go-to-Line dialogs.
- Unsaved-changes warning on New / Open / Quit.

### 5.5 Desktop integration

- Valid `.desktop` file.
- Correct binary name `gslate`.
- Meson install rules that place the binary and desktop file correctly.

## 6. RECOMMENDED ARCHITECTURE (derived from Leafpad)

Keep Leafpad’s modular structure where it helps:

```
src/
  main.c / leafpad.c          → application entry, GtkApplication (or GtkWindow for GTK2/3)
  main_window.c / window.c    → window, menus, actions
  editor.c / textview.c       → GtkTextView / GtkTextBuffer ownership
  gutter.c / linen.c         → line-number drawing (modernise the existing linenum.c)
  config.c                    → NEW: GKeyFile configuration manager
  keybindings.c               → NEW or extended: accelerator handling
  file.c                      → keep / modernise file I/O
  clipboard.c                 → NEW or extended: plain-text paste pipeline
  ...
```

Modernise:

- Replace GTK2-only calls with GTK3 or GTK4 equivalents.
- Prefer `GtkApplication` + `GAction` / `GMenu` for the menu and shortcut system.
- Use CSS providers for colours and border instead of hard-coded GdkColors.
- Use `GtkTextBuffer`’s native undo when available (GTK ≥ 4.6 / 4.16 preferred).
