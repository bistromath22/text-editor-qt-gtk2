7. DOCUMENT MODEL AND PLAIN-TEXT INVARIANTS
======================================================================

Maintain exactly one authoritative text document model using Qt's text
framework. QTextEdit backed by QTextDocument is the reference approach and is
acceptable. A different Qt editor widget is allowed only if it demonstrably
supports every required behaviour: logical paragraph structure, line-height
and margins, clipboard interception, undo/redo, cursor/selection handling,
line-number mapping, and Unicode rendering. Explain the choice in the design
note.

Plain-text contract:
- Disable rich-text acceptance.
- Do not import clipboard HTML/rich formatting.
- Do not save HTML or QTextDocument internal markup.
- Do not insert images, tables, fonts, colors, or embedded objects.
- Internal paragraph formatting is presentation only; it must not leak into
  saved text.
- Save/export through plain-text APIs and UTF-8 encoding.

Logical newline contract:
- One logical paragraph break corresponds to a document block boundary.
- A visual wrapped row is not a logical newline.
- Resizing the window or changing word wrap must never alter text content.
- Empty paragraphs and consecutive empty paragraphs must be preserved.
- Leading and trailing newlines must be preserved by the documented policy.
- The document structure, not a parallel array of line strings, is the source
  of truth.

Canonical input normalization:
1. Replace CRLF (\r\n) with LF (\n).
2. Replace any remaining CR (\r) with LF (\n).
3. Preserve all LF characters, including repeated, leading, and trailing LF.
4. Insert normalized text through Qt document/cursor APIs.

The order matters. Replacing CR before CRLF can accidentally turn one CRLF
into two LF characters. Centralize this logic in a small tested utility.

Canonical internal/export representation is LF. Saving writes UTF-8 with LF
line endings for deterministic output. If a future option supports another
line-ending mode, perform conversion only at the file-output boundary and
test it independently.

Round-trip invariant:
For supported UTF-8 input, load/paste followed by plain-text export must
preserve the exact logical character and paragraph-break sequence, except
for the explicitly documented CRLF/CR-to-LF normalization and UTF-8 BOM
policy. Empty documents, empty blocks, and a final trailing newline must be
tested specifically.

======================================================================
8. ENTER, PASTE, COPY, CUT, UNDO, AND REDO
======================================================================

Treat keyboard editing and clipboard editing as equally important. This is a
high-priority area and must be implemented deliberately rather than relying
on accidental default QTextEdit behaviour.

A. Enter/Return
- Pressing Enter or Return inserts exactly one logical paragraph break.
- It works in non-empty paragraphs, empty paragraphs, adjacent empty
  paragraphs, and at the start or end of a paragraph.
- It works when a selection is active and replaces the selection once.
- Repeated Enter presses create exactly the expected number of blank blocks.
- It must not be swallowed or converted to a visual wrap.
- Paragraph formatting is correct on both sides of the break.
- Modified Enter combinations are not intercepted unless explicitly
  assigned a documented meaning.
- Enter is one normal undoable edit.

B. Paste
Implement a deliberate plain-text paste pathway. In a QTextEdit-based design,
consider overriding insertFromMimeData(const QMimeData *source). Do not rely
on undocumented assumptions about Qt's default rich-text paste path.

Paste procedure:
1. Check whether MIME data offers text/plain or a supported plain-text
   representation.
2. Read text only. Ignore HTML and rich formatting even if both plain text
   and HTML are available.
3. Normalize CRLF and CR to LF.
4. Insert at the current cursor and replace the active selection when present.
5. Preserve leading, internal, repeated, and trailing newlines exactly under
   the canonical policy.
6. Apply configured paragraph metrics to all affected blocks.
7. Leave the cursor at the end of inserted text unless a documented edge case
   requires otherwise.
8. Refresh current-line highlighting, line numbers, gutter geometry,
   scrollbar range, and status-bar position.
9. Ensure the final inserted line can be scrolled fully into view.
10. Treat the entire multiline paste as one logical undo step.
11. Mark document modified as a normal edit; do not generate redundant
    modification notifications.
12. Support paste into an empty document, at the beginning/middle/end of an
    existing paragraph, over a selection, and beside empty paragraphs.
13. Ensure document layout and scrollbar calculations are valid after Qt has
    completed the affected layout pass.

Use an explicit edit transaction such as QTextCursor beginEditBlock/endEditBlock
for the inserted text and related changes where appropriate. Do not allow
formatting housekeeping to fragment one paste into several undo entries.

For MIME data without text, ignore it safely. Never insert an image or rich
document object. Do not fall back to a base paste implementation that can
introduce rich content.

C. Copy and cut
- Copy exports the selected text only as plain text.
- Clipboard payload must not include HTML, editor colors, fonts, paragraph
  formatting, or embedded objects.
- Use LF as the canonical clipboard paragraph separator.
- Cut copies plain text and deletes the selection as one ordinary undoable
  document edit.
- Selection across multiple blocks must retain the intended newline sequence.
- Empty selection handling must be safe and unsurprising.

D. Undo and redo
- A multiline paste undoes in one action and redoes in one action.
- Enter and cut are undoable.
- Undo/redo restores text and logical block structure exactly.
- Formatting maintenance does not add unwanted user-visible undo entries.
- Applying appearance-only settings does not mark a clean document modified.
- Loading a file establishes a clean undo/modified baseline.
- Undo back to the saved state returns the document to clean state where Qt's
  document modified-state semantics permit it.

E. Formatting after insertion
Do not apply paragraph formatting synchronously from a generic blockCountChanged
handler. The reference identified that doing so can interfere with Qt's
intermediate empty-block creation and consecutive blank lines.

Use controlled editing-operation boundaries:
- Capture the cursor/affected block range.
- Begin the edit transaction.
- Insert normalized text or a paragraph break.
- Identify the affected blocks.
- Apply the configured paragraph formatting policy without corrupting the
  text or undo model.
- End the transaction.
- Restore the expected cursor.
- Allow document layout to settle and then update gutter/scroll/highlight.

Do not reformat the entire document after every keystroke unless profiling
proves it necessary. A global font or line-height change may update all blocks
through a safe, efficient presentation-only operation.

======================================================================
9. LINE HEIGHT AND PARAGRAPH SPACING
======================================================================

The configured default line_height is 1.4, representing approximately 140%
of the natural font line height.

Support:
- line_height: proportional line-height multiplier.
- pixels_above: extra paragraph space above each logical block.
- pixels_below: extra paragraph space below each logical block.
- line_distance: retained compatibility setting; define and implement its
  exact effect, or deprecate it explicitly with a migration note. Never
  silently ignore a configured non-zero value.

Prefer a proportional Qt paragraph-height model when suitable. Evaluate
QTextBlockFormat::ProportionalHeight with 140.0 for a multiplier of 1.4.
Avoid fixed pixel line heights calculated once from the default font metrics:
they may clip tall fallback-font glyphs or behave incorrectly after font
changes.

Define the settings so spacing is not double-counted. One possible policy is:
- line_height controls the line box within a block.
- pixels_above and pixels_below control paragraph margins between blocks.
- line_distance is an additional, separately documented additive line-gap
  value only if it can be implemented without clipping and without applying
  paragraph spacing twice.

If Qt's chosen text layout engine cannot combine the requested values
reliably, choose the safest predictable interpretation and document it.
Never silently reinterpret one setting as another.

All existing blocks, blocks created by Enter, and blocks created by paste
must use the same presentation policy. Font changes, pasted emoji, combining
marks, CJK text, and fallback-font glyphs must not be vertically clipped.

Updating line height, font, or spacing must not alter plain-text content,
cursor position, selection, saved state, or undo history unnecessarily.

10. LINE-NUMBER GUTTER, CURRENT-LINE HIGHLIGHT, AND EDITOR GEOMETRY

A. Logical line numbers
- Provide an optional left-side gutter.
- Number logical paragraphs/document blocks, not visual wrapped rows.
- The first logical block is line 1.
- Update the gutter when text is inserted, deleted, loaded, pasted, undone,

- Recalculate width at digit boundaries such as 9 to 10 and 99 to 100.
- Scroll the gutter vertically with the text viewport.
- Align each number with the top/baseline of its corresponding document block,
  even when a paragraph wraps across multiple visual rows.
- Derive positions from Qt document layout/block geometry rather than
  assuming one visual row per block.
- Hiding line numbers must reclaim the gutter width cleanly.
- Do not let gutter visibility change text or paragraph settings.
- Use configured gutter_background_color and line_number_color.

B. Current-line highlighting
- Highlight the logical block containing the text cursor.
- Extend the highlight across the visible text viewport width.
- Use current_line_color.
- Update on cursor movement, selection changes, document edits, undo/redo,
  load, and relevant configuration changes.
- Do not change document text, modified state, or undo history.

C. Geometry and scrolling
- Keep gutter, editor viewport, outer surround, and status bar aligned after
  resize, font changes, border changes, line-number toggles, DPI changes, and
  word-wrap changes.
- Use Qt logical coordinates and layout-managed widget geometry.
- The final visible line must be fully reachable by scrolling.
- Large multiline paste must update scrollbar range correctly.
- No editor viewport may overlap the status bar.
- No unexplained bottom gap may appear in normal, maximized, or full-screen
  mode.
- No fixed-height empty spacer may be introduced to conceal a layout bug.

11. EDITOR SURROUND, BORDER COLOR, AND SAFE QT PAINTING
======================================================================

This requirement is especially important and is carried forward from the
expanded reference prompt.

A. Distinguish the QSlate editor surround from the OS window frame
- border_color controls QSlate's own visible editor surround/frame.
- border_size is the thickness of that surround in Qt logical pixels.
- border_color does NOT control the native desktop title bar, window frame,
  window-manager decorations, or shell chrome.
- Explain this distinction in README and technical design documentation.

B. Define clear widget ownership
- Prefer a dedicated outer frame/container widget that owns the editor and
  paints or styles the editor surround.
- Place the editor and gutter inside it using a layout with explicit margins.
- Apply validated border_color to the widget that actually owns and paints
  the surround.
- The text viewport must independently use background_color.
- The gutter must independently use gutter_background_color.
- Current-line highlight and status bar retain their own configured colors.
- Do not assume QPalette::Window automatically paints every unused area of a
  QAbstractScrollArea/QTextEdit.
- Do not use a status bar, blank spacer, or accidental viewport margin as a
  substitute for the border.
- border_size == 0 removes the surround completely and cleanly.
- Changing border_size recalculates layout geometry but must not change text,
  cursor, selection, undo history, or modified state.

C. Respect QAbstractScrollArea and paint-event contracts
- QTextEdit is based on QAbstractScrollArea and its text is drawn in its
  viewport child; the outer widget and viewport are different paint devices.
- Never construct QPainter(this) inside a viewport paint event to paint the
  outer editor widget.
- Never call QPainter::begin(this), fillRect(), or another painter method on
  a widget that does not own the current paint event.
- Never paint the outer widget from the viewport's paint event.
- If custom painting is necessary, paint only the widget whose own paintEvent
  is executing, or use a dedicated frame widget that paints itself.
- Use Qt's normal frame painting, palette, stylesheet, or dedicated
  container where appropriate.
- Do not suppress or hide QPainter warnings. Remove the invalid painting
  operation itself.
- Do not add conflicting paintEvent overrides or call QFrame/QTextEdit paint
  implementations in an unverified order.

D. Runtime border behaviour
- Parse border_color with QColor and reject invalid values.
- Apply the valid color to the actual border-owning widget.
- Repainting occurs immediately after border_color reload.
- Geometry updates after border_size reload.
- A valid configured color must not be replaced silently by a platform
  palette default.
- If a stylesheet is used, control selector specificity and object names so
  no unrelated rule overrides the configured color.
- Do not hard-code a light-grey or white border.

E. Border tests
Automated tests must verify:
- A non-default border_color is loaded and retained in EditorConfig.
- Applying config changes the actual border-owning widget's palette/style or

14. FILE LOADING, SAVING, AND COMMAND-LINE PATHS

- Choose normal startup geometry unless an explicit project decision calls
