5. CONFIGURATION FILE CONTRACT
================================================================================

Use a human-editable INI file named config.ini with [editor] and [shortcuts]
sections. A small self-contained C++ parser is preferred so the exact syntax,
comments, duplicate handling, warnings, and preservation rules are explicit.
wxFileConfig is an acceptable alternative only if the implementation proves
that it preserves every required key/value spelling and supports the precise
validation and forward-compatibility rules below. Do not use wxConfigBase or
platform registry settings as the sole configuration store.

Required parser behaviour:
- Section headers such as [editor] and [shortcuts].
- key=value pairs.
- Leading/trailing whitespace around keys and values.
- Blank lines.
- Full-line comments beginning with # or ;.
- Preserve colour values beginning with #; do not parse the leading colour
  marker as an inline comment.
- Case-insensitive booleans true/false (optionally yes/no and 1/0).
- Numeric parsing with strict full-string consumption.
- Reject NaN, infinity, overflow, underflow where invalid, and trailing junk.
- Validate #RRGGBB colours and non-empty font family.
- Duplicate keys: last occurrence wins and emits a diagnostic.
- Unknown keys: warn, retain/ignore safely, and do not crash.
- Unknown sections: warn and ignore safely.
- Malformed lines: report line number and continue only where recovery is safe.
- Missing configuration file: use canonical defaults.
- Partial config: unspecified keys inherit canonical defaults.
- Unreadable/invalid explicit config path: report clearly and follow one
  documented deterministic policy (prefer exit nonzero for explicit path;
  never silently search and activate a different file).
- Invalid individual values: keep that property's compiled-in default, report
  the key and reason, and continue if the file structure remains parseable.
- Parse into a temporary Config object, validate the full candidate, and apply
  atomically only after successful parse. A failed reload must not partially
  mutate the active runtime configuration.

Define the canonical defaults exactly once in a single ConfigDefaults factory
or constexpr/static Config object. Startup, fallback handling, config.example.ini
generation, --print-config, tests, and menu shortcut fallbacks must all derive
from that source. Do not keep separate handwritten defaults in the GUI,
parser, README sample, or command-line printer.

Numeric validation policy (one shared validator for parsing and runtime font
commands):
- border_size: 0..128 logical pixels.
- font_size: 6..96 points.
- line_height: finite 0.5..5.0.
- pixels_above: finite 0..100.
- pixels_below: finite 0..100.
- line_distance: finite 0..100.
- Colours: exactly #RRGGBB unless alpha is deliberately added consistently.
- Boolean: strict true/false plus explicitly documented aliases.

If values are outside the stated ranges, retain the canonical default for that
property and emit a diagnostic. Do not clamp silently. Keep original settings
and values available to --print-config only when they are valid; output must
always represent the canonical defaults, not a corrupted runtime state.

================================================================================
7. UTF-8, NEWLINES, FILE LOAD/SAVE, AND ROUND-TRIP
================================================================================

### 7.1 Canonical newline policy

Internal document line endings are LF (\n). Every external text input boundary
must normalize in this order:
1. CRLF (\r\n) becomes exactly one LF.
2. Remaining CR (\r) becomes LF.
3. Existing LF remains LF.

Preserve every intentional leading newline, repeated blank line, empty line,
and trailing newline. Never normalize a CRLF pair into two LF characters.
Word wrapping is visual only and must not insert document newline bytes.

Implement newline normalization in a standalone pure helper and unit-test it.
Also provide the inverse/serialization contract only if a different on-disk EOL
mode is ever intentionally added. The current default is UTF-8 with LF output.

### 7.2 UTF-8 policy

Read files as bytes. Validate the complete byte sequence as strict UTF-8 before
changing the active editor. Strip one UTF-8 BOM only at the beginning of a
loaded file and document this policy. Normalize newlines. Reject invalid UTF-8
with a useful diagnostic and leave the current document, filename, cursor,
undo history, and dirty state untouched. Do not silently replace malformed
bytes or reinterpret them using a local code page.

Scintilla positions are byte-oriented. Never use a UTF-8 byte offset as a
visible character column. Use the control's documented character-count and
position-relative functions where possible. If a helper is required, validate
UTF-8 boundaries and test it using multi-byte characters. Do not split a
multi-byte code point when selecting or inserting text.

Define the status-bar column explicitly as a 1-based Unicode code-point count
within the logical line (not UTF-8 bytes). Combining marks count as separate
code points unless grapheme-cluster segmentation is explicitly implemented
and documented. Never label a byte count as a character column.

Reject embedded NUL bytes unless the exact wxStyledTextCtrl/Scintilla path
used by the implementation is proven to store, retrieve, paste, and save them
without truncation. Do not silently truncate a document at NUL.

### 7.3 File loading

1. Resolve the selected path as a wxString/wxFileName without lossy path
   conversion.
2. Read bytes with checked error handling.
3. Detect and strip an optional UTF-8 BOM.
4. Validate UTF-8 and reject invalid input before altering the editor.
5. Normalize CRLF/CR to LF.
6. Set Scintilla to UTF-8 and LF mode.
7. Load the validated UTF-8 text in one controlled operation.
8. Disable undo collection or otherwise reset the undo buffer safely during
   initial loading; then call EmptyUndoBuffer() and SetSavePoint(). Verify the
   actual behaviour for the selected Scintilla build.
9. Set current path only after the complete load succeeds.
10. Reset dirty state and update title, line count, status, gutter, and scroll.

Opening a file that fails must never blank or replace the existing document.
Do not create an undo action that can restore text from the previous file.

### 7.4 Safe file saving

Save only UTF-8 document bytes with LF endings. Do not serialize style data or
widget state. Use safe replacement so a failed save does not truncate or
corrupt an existing destination.

Preferred robust strategy:
- Write to a unique temporary file in the destination directory.
- Use checked write loops; handle short writes and interruptions.
- Flush user-space buffers and call the platform durability operation where
  appropriate (fsync/FlushFileBuffers).
- Close successfully.
- Atomically replace the destination using the correct platform primitive.
- Clean up the temporary file on every failure path.
- Preserve existing file permissions/metadata where feasible and document
  exactly what is preserved.

On POSIX, a same-directory mkstemp + write + fsync + rename implementation is
acceptable. On Windows, use Unicode-safe Windows file APIs and a replace/move
operation with replace-existing semantics; do not assume std::filesystem::rename
has identical replace behaviour on every platform. Isolate these details in a
small platform-safe file utility.

Do not mark the document clean or change the current path after a failed save.
For Save As, change filename/title only after the atomic replacement succeeds.
Handle read-only files, permissions, missing directories, disk-full errors,
invalid paths, and failed renames without crashing or losing original data.

### 7.5 Round-trip invariant

For supported UTF-8 input, load -> editor text -> save must preserve every text
code point and logical LF boundary, subject only to documented BOM stripping
and newline normalization. Empty file and a file ending in a newline are
different documents and must remain different after round-trip.

Test empty input, one line, leading newline, trailing newline, multiple
consecutive blank lines, non-ASCII scripts, combining marks, emoji, and large
files. Also test load failure and save failure without document loss.

================================================================================
8. ENTER, CLIPBOARD, CUT/COPY/PASTE, UNDO, AND REDO
================================================================================

### 8.1 Enter and typing

Prefer Scintilla's native Enter/newline handling. Set the EOL mode to LF.
Pressing Enter inserts exactly one logical LF. Test Enter:
- In the middle of a non-empty line.
- At the start/end of a line.
- In an empty line.
- Repeatedly to create multiple blank lines.
- With a selection active (selection becomes one newline).
- Adjacent to pre-existing blank lines.

Do not intercept ordinary typing without a demonstrated reason. Cursor,
selection, and undo behaviour must remain native and predictable.

### 8.2 Clipboard pipeline

Use wxWidgets clipboard APIs and wxTextDataObject for plain text. On Linux,
Windows, and supported wx ports, use the standard system clipboard. Ensure the
application's menu actions and configured shortcuts route to one dispatcher.

Copy:
- Copy exactly the current selection as UTF-8 plain text.
- Do not copy formatting, styles, markers, margins, or embedded objects.
- Preserve all selected logical newlines.
- If no selection exists, do nothing (unless a clearly documented alternative
  is deliberately implemented).

Cut:
1. Obtain the selected plain text.
2. Open the clipboard and set wxTextDataObject text.
3. Close/release clipboard on every code path.
4. Only after clipboard ownership/set succeeds, remove the selection.
5. Group deletion as one undoable edit where necessary.
6. On clipboard failure, do not delete the selected text.

Paste:
1. Open/read clipboard as plain text only.
2. Safely close the clipboard even on exceptions/errors.
3. Reject/ignore unsupported non-text data without corrupting the document.
4. Normalize CRLF/CR to LF.
5. Convert to UTF-8 with a checked conversion.
6. Replace selected text at the intended insertion point.
7. Preserve leading/internal/repeated/trailing newlines.
8. Move caret to the end of inserted content.
9. Keep scrolling/caret visible.
10. Update dirty state, title, status, line-number margin, and current-line
    display.
11. Group the complete multiline paste into one Scintilla undo transaction
    using BeginUndoAction()/EndUndoAction(). Ensure EndUndoAction() is called
    on every normal and exceptional exit.

Clipboard access is synchronous in the usual wxWidgets desktop API, but do not
assume it cannot fail or block. If an asynchronous implementation is chosen,
retain the intended selection/insertion point using a carefully managed
Scintilla position/anchor strategy and document the behaviour when the user
edits before the paste completes.

Do not let a native Scintilla Ctrl+V binding bypass newline normalization. Test
keyboard paste and menu paste. If overriding the control's key handling, call
the native path for unrelated keys and prevent double invocation. Drag/drop
text should be tested; where the platform can insert CRLF directly, normalize
it safely without breaking native drop selection behaviour.

### 8.3 Undo and redo

Use Scintilla's built-in undo system. Do not add a separate undo engine.
- Verify CanUndo/CanRedo, Undo/Redo, EmptyUndoBuffer, SetSavePoint.
- Menu and shortcut actions call the same dispatcher.
- Multiline paste is one logical undo operation.
- Cut is undoable.
- Enter operations undo correctly.
- Typing and selection replacement remain intuitive.
- Loading a new document resets the previous document's undo history.
- Successful save sets a save point; failed save does not.
- Undo back to save point clears modified state; redo past it restores it.
- Appearance/configuration changes do not affect text undo history.

Use Scintilla's modification notifications (e.g. wxEVT_STC_CHANGE and/or
wxEVT_STC_MODIFIED as appropriate) and update events (e.g. wxEVT_STC_UPDATEUI)
only as documented by the actual wxWidgets version. Avoid redundant full UI
updates for every notification.

9. WORD WRAP, CARET STYLE, BLINK, AND LINE HEIGHT
================================================================================

### 9.1 Word wrapping

wordwrap=true: SetWrapMode(wxSTC_WRAP_WORD) or the verified word-wrap mode.
wordwrap=false: SetWrapMode(wxSTC_WRAP_NONE).

Wrapping is visual only and must not change the underlying text. Recalculate
layout on resize and config reload. Horizontal scrolling should be available
when wrap is disabled and suppressed/unused when wrap is enabled according to
Scintilla's native behaviour.

### 9.2 Block cursor and blink

Use the actual Scintilla caret APIs exposed through wxStyledTextCtrl:
- block_cursor=true: SetCaretStyle(wxSTC_CARETSTYLE_BLOCK).
- block_cursor=false: SetCaretStyle(wxSTC_CARETSTYLE_LINE).
- block_cursor_blink=false: SetCaretPeriod(0), which Scintilla documents as a
  steady, non-blinking caret.

When block_cursor_blink=true, use the platform/control default blink period or
an explicit documented period. Do not change the global OS caret policy.
Use a caret colour with enough contrast against the editor background and
text. Test focus loss/gain, selection, Unicode characters, combining marks,
emoji, overwrite mode if available, resize, scroll, and redraw.

Scintilla's block caret is a filled/block-style caret, unlike FLTK's outlined
block cursor. Document the wxStyledTextCtrl/Scintilla appearance actually
observed; do not reuse the FLTK limitation statement.

### 9.3 Line height and spacing options

The config keys line_height, pixels_above, pixels_below, and line_distance
must remain present, parseable, validated, visible in --print-config, and
preserved in config.example.ini.

Scintilla uses a common line height for the document/display lines. Public
Scintilla APIs SCI_SETEXTRAASCENT and SCI_SETEXTRADESCENT (exposed as
wxStyledTextCtrl SetExtraAscent/SetExtraDescent in compatible wrappers) add
vertical space globally to line metrics. They do not provide separate
per-paragraph top/bottom margins or a distinct wrapped-subline spacing model.

Investigate the actual wxWidgets 3.2 wrapper and bundled Scintilla version.
If supported, implement line_height=1.4 as a carefully calculated global line
height approximation:
1. Apply the resolved font to the default style.
2. Reset extra ascent/descent to zero.
3. Query the natural line height using a documented control metric method
   after the font has been applied (e.g. TextHeight for a valid line/style).
4. Compute desired height = round(natural_height * line_height).
5. Compute positive extra pixels = max(0, desired - natural_height).
6. Distribute extra pixels between ascent and descent in a stable, documented
   way (approximately half each; remainder deterministic).
7. Apply and redraw; recalculate after font-size/family changes.
8. Verify caret positioning, hit testing, wrapped lines, selection, scrolling,
   line numbers, combining characters, and emoji are not clipped or displaced.

Do not accumulate extra pixels each time configuration is reloaded. Always
recompute from a zero-extra baseline. Do not fake line height by changing the
configured font size.

For line_height values below 1.0, negative extra ascent/descent may cause glyph
overlap or clipping. Implement compression only if documented, safe, and
visually tested. Otherwise retain/validate the requested value, report that
compression is unsupported, and use the natural line height as the effective
fallback.

pixels_above and pixels_below mean independent extra space around logical
paragraphs. Scintilla's uniform line model does not provide exact per-paragraph
margins. Do not simulate them by inserting blank lines, changing font sizes,
or creating hidden characters. Preserve and print values. If nonzero values
are configured and no reliable public implementation exists, emit a warning
and document the unsupported effective behaviour.

line_distance means extra spacing between visual wrapped sublines in the
legacy configuration. Global Scintilla line metrics also affect unwrapped
lines; they are not a separate wrapped-line-only setting. Do not claim exact
support unless a documented API and tests prove it. Since the supplied default
is zero, preserve zero without extra work. For a nonzero value, either provide a
clearly documented global approximation with an explicit diagnostic or leave
it unapplied with a warning. Do not silently ignore it.

Document the requested value and effective behaviour separately in diagnostics
or a settings report. Do not access Scintilla private internals or draw fake
text rows to imitate paragraph spacing.

10. LINE-NUMBER GUTTER, CURRENT-LINE HIGHLIGHT, AND STATUS BAR
================================================================================

### 10.1 Built-in line-number margin

Use Scintilla's built-in numeric margin rather than a separately scrolling
custom widget.

Recommended design:
- Reserve a margin index (e.g. margin 0) for line numbers.
- Set its type to wxSTC_MARGIN_NUMBER.
- Set the margin mask appropriately.
- Set line-number style foreground to line_number_color and background to
  gutter_background_color (using the Scintilla line-number style constant).
- Use the configured monospace font and a suitable line-number font size.
- Use TextWidth() and the current logical line count to measure the required
  digit width, plus a small horizontal inset.
- Recalculate at 9 -> 10, 99 -> 100, 999 -> 1000, and after font size changes.
- Set width to zero when show_line_numbers=false so the editor reclaims space.
- Do not number visual wrapped rows as separate logical lines.

The gutter must remain aligned during scroll, wrap, font changes, resize,
full-screen transitions, and large paste. No separate scrolling surface is
allowed unless there is a specific tested reason the native margin cannot meet
the requirement.

### 10.2 Current-line highlighting

Use Scintilla's native caret-line feature:
- SetCaretLineVisible(highlight_current_line).
- SetCaretLineBackground(current_line_color).
- Use whole logical line highlighting, not only the wrapped visual subline.
- Keep visibility and colour synchronized after caret movement, selection,
  load, edit, undo/redo, config reload, and focus changes.

Highlighting is presentation only and must not modify document text, create
undo actions, or mark the document modified.

### 10.3 Optional status bar

show_statusbar controls a real bottom status row. When visible, show a 1-based
logical line and 1-based Unicode code-point column, for example:

    Ln 12, Col 5

Update after typing, cursor movement, mouse positioning, selection movement,
paste, undo/redo, file load, Go to Line, and any cursor relocation. Use the
Scintilla update UI event to update only when relevant state changes.

When disabled, hide/destroy the status row cleanly and allow the editor to use
the reclaimed height. Do not leave a permanent blank strip or use a spacer as a
layout patch. The status row is not editor bottom padding.

11. BORDER, CONTENT INSETS, AND WINDOW LAYOUT
================================================================================

Implement the configured editor border as an application-owned surround,
independent of the operating-system window decorations. wxWidgets does not
own or promise to recolour the Ubuntu window-manager title bar/frame.

Recommended design:
- wxFrame main window.
- Vertical root sizer.
- Menu bar at the top.
- A border-owning wxPanel (or small dedicated container class) around the
  editor region.
- The border-owning panel paints/owns border_color as its background.
- A child editor panel/control is inset by border_size using sizer geometry or
  a small custom border container.
- The wxStyledTextCtrl fills the available inner area.
- Optional status row at the bottom.

Use wxWidgets public drawing/layout APIs only. Keep the actual border owner
clear. If a nested panel is used, ensure all four sides are visible and the
configured colour is not covered by the editor's background. A border size of
zero removes the surround; a positive size produces all intended sides.

Keep these distinct:
1. Editor border thickness.
2. Text control's left/right/top/bottom padding/margins.
3. Line-number margin.
4. Status-row height.
5. Native OS window decorations.

Changing border thickness/colour must not modify text, cursor, selection,
scroll position unnecessarily, undo history, or dirty state. Apply DIP-aware
sizing using wxWidgets conversion methods where appropriate; document whether
configuration pixel values are logical DIP units and ensure consistent
behaviour on high-DPI displays.

Do not:
- Change the native Ubuntu title bar and claim it is the editor border.
- Use arbitrary bottom spacers to hide a layout issue.
- Make the status row part of the border.
- Use fixed absolute coordinates for the whole layout.
- Paint over the text control's native rendering surface.
- Use unsupported platform-specific hacks for ordinary border geometry.

Resize and layout must work in normal, maximized, restored, full-screen, and
minimum supported dimensions. Preserve cursor, selection, and scroll state.
No clipping, empty bottom region, gutter drift, or overlap is acceptable.

Provide traditional File, Edit, and View menus. Every command must have one
central action handler. Menu invocation, configured accelerator invocation,
and any editor-specific key handler must route to that same action. Do not
implement different copies of Save, Undo, Paste, or other actions.

### 12.1 Required menus and shortcut defaults

FILE

- Open... — <Primary>o
- Save — <Primary>s
- Save As... — <Primary><Shift>s
- Quit — <Primary>q

EDIT
- Undo — <Primary>z
- Redo — <Primary>y
- Cut — <Primary>x
- Copy — <Primary>c
- Paste — <Primary>v
- Find... — <Primary>f
- Find Next — F3
- Go to Line... — <Primary>g

VIEW

The values shown above are fallback defaults from the configuration contract.

### 12.2 ShortcutParser

Implement a standalone ShortcutParser that converts the stored GTK-style
spellings into wxAcceleratorEntry flags and key codes.

Required syntax:
- <Primary> means Ctrl on Ubuntu/Linux and Windows.
- <Shift> maps to wxACCEL_SHIFT.
- Recognize F1 through F24 when supported by wxWidgets/platform.
- Recognize ordinary ASCII letters and documented punctuation.
- Recognize plus and minus deterministically.
- Reject malformed or unsupported spellings with a warning.
- For an invalid config shortcut, keep that action's compiled-in default.
- Detect duplicate assignments; resolve with a deterministic policy, log the
  collision, and ensure no menu action becomes unreachable.
- Render the visible accelerator label from the same parsed representation.

For plus, account for common keyboard layouts where the top-row plus requires
Shift with Equal, plus a separate numeric-keypad Add key. Define and document
which physical combinations are supported. For minus, support the top-row
minus and keypad Subtract where practical. Test actual key events on Ubuntu
and Windows; do not assume the textual label and physical key code are
interchangeable.

wxAcceleratorTable on the frame is the preferred app-level mapping. Test every
shortcut while focus is inside wxStyledTextCtrl; some Scintilla key handling
may consume an event before the frame accelerator table sees it. If necessary,
add a minimal editor key dispatcher for app commands while preserving native
Scintilla editing behaviour. Never dispatch one physical key twice.

For Undo/Redo/Cut/Copy/Paste, ensure Scintilla's own key bindings and app-level
accelerators are aligned. It is acceptable to let the native control handle a
standard editing command if that is the single path; the menu command must
invoke the same semantic operation. Do not have both the accelerator table
and a custom key event handler trigger the same operation.

On config reload, rebuild the wxAcceleratorTable and refresh menu labels only
after the candidate config and shortcut set have validated successfully.

### 12.3 Find and Find Next

Find opens a simple text-entry dialog. Search from the current insertion
position. Find Next repeats the previous query. Use Scintilla's built-in
search APIs and flags. Default to case-insensitive search unless an explicit
simple case-sensitivity option is implemented. On reaching document end,
wrap once and report that wrap where useful. If no match exists, do not jump to
an unrelated position or destroy the current selection.

### 12.4 Go to Line

Accept a 1-based logical line. Validate 1 <= requested_line <= line_count.
Convert to Scintilla's 0-based line index, move to the start of that logical
line, and ensure the caret is visible. Invalid/empty input must show a useful
message and leave the cursor unchanged. Wrapped visual rows do not count as
separate logical lines.

### 12.5 Font-size actions

Increase/decrease one point per command. Enforce 6..96 points. Update default
style and line-number style consistently, recalculate global line-height
spacing and gutter width, and retain the resolved font family. Font changes
must not edit text, move the cursor, alter undo history, or mark dirty.

### 12.6 Full screen

F11 toggles full screen using wxFrame's documented full-screen API. Ensure
restoring from full screen restores normal/maximized layout and status-bar
visibility without losing editor focus or document state. Keep menu visibility
behaviour simple and documented.

13. FILE MENU, DIRTY STATE, AND ONE-DOCUMENT WORKFLOW
================================================================================

Open, New, Save, Save As, Quit, and window-close handling must be reliable.

### New

Create a new untitled empty document only after handling the current document's
dirty state. Reset undo history and set a clean save point. Clear current path
only after the user chooses to discard/save and the new document is actually
created.

### Open

Use wxFileDialog with an appropriate text/all-files filter. Before replacing
the active document, ask about dirty changes. Do not change the document until
the selected file has been fully read, validated, and normalized. Cancelling
file selection or the unsaved prompt leaves everything untouched.

### Save

Save to the current path. If untitled, delegate to Save As. Only mark clean
after safe replacement succeeds.

### Save As

Use wxFileDialog with overwrite confirmation. Do not change current filename,
window title, or save point before the file has been successfully written and
atomically installed.

### Unsaved-change prompt

Before New, Open, Quit, and window close, if modified, offer:
- Save
- Discard
- Cancel

Save proceeds only if the save succeeds. If Save As is cancelled or fails,
the original action is cancelled. Discard proceeds without saving. Cancel
leaves the active document untouched.

### Dirty state and title

Use Scintilla GetModify()/SetSavePoint() semantics, not a manually maintained
boolean alone. Update title on content changes and save-point changes.
Suggested title:

    wedit — filename.txt
    wedit — filename.txt [modified]
    wedit — Untitled
    wedit — Untitled [modified]

File path must update only after successful load or save-as. Failed file
operations must not lose the active buffer, filename, undo state, or dirty state.

### File error handling

Show clear, specific errors for missing file, permission denied, invalid UTF-8,
read/write failure, disk full, invalid path, read-only destination, and atomic
replacement failure. Do not show success messages for failed operations.

20. AUTOMATED TESTS AND ACCEPTANCE CRITERIA
================================================================================

Use CTest. A small dependency-free C++ test harness is preferred for core
logic. Do not add a large external test framework unless justified. Keep core
utilities independent of GUI initialisation wherever possible. wxWidgets/STC
GUI-specific tests may be a separate executable and run under Xvfb when
available.

### A. Text normalization

Test:
- LF remains LF.
- CRLF becomes one LF.
- CR becomes LF.
- Mixed CRLF/CR/LF normalizes correctly.
- Leading newline preserved.
- Trailing newline preserved.
- Consecutive blank lines preserved.
- Empty input stays empty.
- Large input is handled without truncation.

### B. UTF-8 utilities

Test:
- Valid ASCII.
- Valid multi-byte UTF-8 (e.g. accented Latin, CJK, Indic scripts).
- Combining characters.
- Emoji and variation selectors.
- UTF-8 BOM removal only at the start.
- Invalid continuation bytes.
- Truncated multi-byte sequences.
- Overlong and otherwise invalid encodings.
- Embedded NUL policy.
- Character-column counting versus byte length.
- Position conversions never split code points.

### C. File round trip and atomic save

Test:
- Empty file.
- One-line file without trailing newline.
- File ending with newline.
- Leading newline.
- Several blank lines.
- LF, CRLF, CR, mixed endings.
- UTF-8 non-ASCII, combining marks, emoji.
- BOM input and output policy.
- Invalid UTF-8 rejection leaves active document unchanged.
- Missing file, permission failure, invalid path.
- Failed save leaves the original destination intact.
- Failed Save As does not change filename or clean state.
- Temporary file cleanup on failure.
- Successful replacement sets clean state only after commit.

### D. Configuration

Test:
- Every exact supplied default.
- Built-in toggle_block_cursor default.
- Complete config.
- Partial config.
- Missing config.
- Malformed section and malformed key/value lines.
- Leading/trailing whitespace.
- Full-line # and ; comments.
- #RRGGBB values are not treated as comments.
- Boolean case variations.
- Duplicate key policy (last wins + diagnostic).
- Unknown key/section warning.
- Invalid colour/font/numeric/boolean fallback.
- NaN, infinity, overflow, trailing junk.
- Atomic runtime reload.
- Failed reload preserves live settings.
- --print-config equals the canonical defaults object exactly.
- --print-config-paths order and active-source reporting.
- Reload does not modify text, filename, save point, selection, or undo.

### E. Shortcut parser

Test every supplied shortcut spelling, including:
- <Primary>n/o/s/q/z/y/x/c/v/f/g/r/w/l/h.
- <Primary><Shift>s and <Primary><Shift>b.
- F3 and F11.
- <Primary>plus and <Primary>minus.
- Built-in <Primary>b toggle_block_cursor.

Also test:
- Ctrl mapping on Linux/Windows.
- Shift modifier.
- Top-row and keypad plus/minus mappings.
- Invalid/malformed input fallback.
- Duplicate binding diagnostics and deterministic resolution.
- Menu label generation.
- Rebuild after config reload.
- Shortcuts while editor has focus.
- No double-dispatch with Scintilla's built-in bindings.

### F. Editor behaviour

Test:
- Empty document.
- Insertion and deletion.
- Enter at beginning/middle/end.
- Enter in empty paragraph and repeated blank lines.
- Enter replacing a selection.
- UTF-8 insertion and movement.
- Copy/cut/paste as plain text.
- CRLF/CR/mixed newline paste.
- Leading/trailing clipboard newlines.
- Paste over selection.
- Multiline paste as one undo action.
- Undo/redo exact text restoration.
- Load resets old undo history.
- Save point and modified-state transitions.
- Find and Find Next wrap.
- Go to Line validation.
- Logical line counting under wrapping.

### G. Gutter and current-line display

Test:
- 1, 9, 10, 99, 100, 999, and 1000 logical lines.
- Dynamic line-number margin width.
- Gutter hidden width is zero/reclaimed.
- Wrapped rows do not increment logical line numbers.
- Scrolling and large paste.
- Font size changes.
- Resize/full-screen.
- Current-line toggle and colour.
- Cursor moves by keyboard and mouse.

### H. Caret and typography

Test:
- block cursor on/off.
- caret blink disabled by period zero.
- configured font resolution and fallback.
- font size min/max.
- line_height 1.4 global spacing approximation.
- recomputation after font size change/reload does not accumulate spacing.
- zero spacing values.
- nonzero unsupported paragraph settings produce warnings.
- Unicode fallback glyphs, combining marks, emoji, wrapped lines, selection,
  cursor hit-testing, and scroll are not clipped by line metrics.

### I. Layout and border manual verification

Run the GUI and inspect:

- Minimum dimensions.
- Maximized and restored windows.
- Full screen and return.
- Window resize and high-DPI scaling.
- Border size zero and 20.
- Custom border colour.
- Gutter on/off.
- Status bar on/off.
- Wrap on/off.
- Small and large font.
- Long documents and long unwrapped lines.
- Large multiline paste and final-line scrolling.

Verify:
- No unexpected bottom strip.
- No border side missing or covered by editor background.
- No gutter misalignment or overlap.
- No status bar overlap.
- No text or Unicode clipping.
- No lost cursor/selection after configuration reload.
- No text mutation from visual settings.
- No crash on file or clipboard failures.

Document which tests are automated and which need manual GUI inspection. Do
not weaken tests to make them pass. Never report an unrun test as passed.

23. KNOWN IMPLEMENTATION RISKS — DO NOT REPEAT THESE DEFECTS
================================================================================

1. Do not use wxTextCtrl as a shortcut around a missing STC component without
   reporting that the required editor architecture changed.
2. Do not enable a syntax lexer or syntax styling; this remains plain text.
3. Do not assume Scintilla positions are Unicode character indexes; they are
   byte-oriented document positions.
4. Do not split a UTF-8 character while computing positions or columns.
5. Do not confuse visual wrapping with stored LF newlines.
6. Do not lose leading, repeated, or trailing blank lines.
7. Do not append a newline automatically on save.
8. Do not load invalid UTF-8 by silently replacing bytes.
9. Do not change the active document before a candidate file is fully read,
   validated, and normalized.
10. Do not change the current filename before successful load/Save As.
11. Do not mark clean after a failed save.
12. Do not truncate an original file on a failed atomic save.
13. Do not let native paste bypass newline normalization.
14. Do not make multiline paste several undo operations.
15. Do not delete selected text if copying to clipboard failed.
16. Do not leave the previous document in the new document's undo history.
17. Do not let appearance/config reload affect text, undo, save point, or dirty
    state.
18. Do not register duplicate accelerator and editor-key handlers for one key.
19. Do not let configured shortcut labels drift from actual accelerator keys.
20. Do not hard-code line-number margin width for only two-digit line counts.
21. Do not count wrapped visual lines as logical document lines.
22. Do not create a separate gutter that scrolls independently from Scintilla.
23. Do not claim pixels_above/pixels_below are per-paragraph features if only
    global line spacing is available.
24. Do not implement line_height by changing font size.
25. Do not accumulate extra ascent/descent on every reload.
26. Do not treat line_distance as wrapped-only spacing if the chosen API affects
    every display line.
27. Do not draw a custom caret or gutter over Scintilla unless required and
    rigorously tested against selection, hit testing, scrolling, and redraw.
28. Do not confuse the editor border with the native Ubuntu window frame.
29. Do not hide layout errors with a fixed bottom spacer.
30. Do not assume border thickness is the same as text padding or gutter width.
31. Do not use hard-coded widget coordinates in place of wx sizers.
32. Do not use GTK4, Qt, FLTK, or platform-specific APIs in the main app.
33. Do not hard-code /usr/lib library paths or guess wxWidgets link names.
34. Do not claim STC linkage based only on wxWidgets core/base being found.
35. Do not delete paths outside the project in install/package scripts.
36. Do not include build artifacts or the archive inside wedit-source.zip.
37. Do not claim a build/test/GUI/Windows check passed unless it was run.
