5. DOCUMENT MODEL AND PLAIN-TEXT RULES
============================================================

The editor must maintain a single, authoritative plain-text document model.

Use Qt's text document model appropriately. A QTextDocument-backed editor is acceptable and likely the simplest approach because the current project depends on QTextBlockFormat paragraph metrics. QTextEdit is the reference implementation. You may choose another Qt text widget only if you prove that it supports all required paragraph-spacing, line-height, cursor, clipboard, undo, and line-number behaviours reliably.

The user-visible document must be plain text:
- No HTML is saved.
- No rich-text styling is imported from the clipboard.
- No fonts, colors, tables, images, or embedded objects are pasted into the document.
- Paragraph formatting used internally to render the document must not leak into the saved plain-text content.

Use a consistent model for newlines:
- A logical paragraph break is a real document paragraph/block boundary.
- A visual wrap caused by the width of the window is not a stored newline.
- Do not insert newline characters into the document merely because a visual line wraps.
- Empty paragraphs must be preserved.
- Consecutive empty paragraphs must be preserved.
- Leading newlines and trailing newlines must be preserved according to the documented plain-text round-trip policy.
- A paste operation must not merge, duplicate, or drop paragraph breaks.

Canonical internal newline policy:
- Normalize external text line endings to LF (\n) at input boundaries.
- Convert CRLF (\r\n) to LF first.
- Convert remaining CR (\r) to LF.
- Do not accidentally turn CRLF into two newlines. The order of normalization matters.
- Insert the normalized text through the Qt document/cursor APIs.
- When exporting plain text, use a documented LF representation internally. If platform-native line endings are desired for file output, convert only at the file-writing boundary.

Prefer Qt's QTextDocument/QTextBlock representation rather than manually inserting special HTML tags or maintaining a second newline array. The document structure should be the source of truth.

Required round-trip invariant:
For supported text input, loading or pasting text, then exporting plain text, must preserve the sequence of logical characters and paragraph breaks, subject only to the explicitly documented newline normalization policy.

6. ENTER, PASTE, COPY, CUT, AND CLIPBOARD CONTRACT
============================================================

This is a critical part of the rewrite. Treat manual editing and clipboard editing as equally important paths.

A. Enter/Return
- Pressing Enter or Return creates exactly one logical paragraph break.
- Enter must work in non-empty paragraphs, empty paragraphs, consecutive blank paragraphs, at the beginning/end of a paragraph, and when a selection is active.
- Repeatedly pressing Enter must create the requested number of empty paragraphs.
- Enter must not be swallowed or converted into a visual wrap.
- Paragraph metrics must remain correct on both sides of the newly created break.
- Enter with documented modifier combinations must behave predictably; do not intercept modified key combinations unless they are explicitly assigned a meaning.

B. Paste
Implement a deliberate clipboard text insertion pathway. In a QTextEdit-based implementation, consider overriding insertFromMimeData(const QMimeData *source). Do not rely on undocumented assumptions about the default paste path.

Paste behaviour:
1. Detect whether the MIME data contains plain text.
2. For text, read it as text and discard rich-text styling/HTML.
3. Normalize CRLF and CR to LF.
4. Insert at the current cursor, replacing the current selection when one exists.
5. Preserve all intentional leading, internal, repeated, and trailing line breaks according to the agreed round-trip rules.
6. Apply the same paragraph line-height and margin policy used for manually entered paragraphs.
7. Keep cursor placement predictable, normally at the end of the inserted text.
8. Keep current-line highlighting and line numbers in sync.
9. Update scrollbar range and cursor visibility after the document layout has settled.
10. Mark the document modified exactly once as an ordinary edit.
11. Make the complete paste, including any required format normalization, one logical undo step.
12. Support pasting into an empty document, into the middle of a paragraph, at the start/end of a paragraph, over a selection, and adjacent to empty paragraphs.

For non-text MIME data, follow an explicitly documented policy. Since Slate is a plain-text editor, do not insert images or rich document objects. If no supported text representation exists, ignore the paste safely or use Qt's base behaviour only if it cannot introduce non-text content.

C. Copy and cut
- Copy exports the selected text as plain text.
- Copy must not export editor colors, font information, block formatting, HTML, or embedded objects.
- Newline separators in clipboard text must be consistent and documented; use LF as the canonical application representation.
- Cut must copy plain text and remove the selection as one normal undoable edit.
- Selection boundaries spanning paragraphs must retain their exact logical newline structure.

D. Undo/redo
- A multiline paste must undo in one action and redo in one action.
- Enter operations must be undoable.
- Formatting maintenance must not create separate user-visible undo entries.
- Applying editor appearance settings must not mark an otherwise clean file as modified.
- Undo/redo must restore text and paragraph boundaries exactly.

E. Formatting after insertion
Do not try to repair pasted blocks synchronously from a generic blockCountChanged signal. The reference implementation deliberately disabled that approach because formatting during Qt's empty-block insertion could interfere with consecutive blank lines.

Instead, use a controlled operation boundary:
- begin an edit transaction;
- perform the normalized text insertion;
- identify affected document blocks;
- apply the editor's paragraph-format policy to those blocks;
- end the transaction;
- restore the cursor;
- allow/update document layout and repaint.

Avoid reformatting the entire document after every keypress or paste unless profiling demonstrates that it is necessary. For font or global line-height changes, update all document blocks safely and efficiently.

7. LINE HEIGHT AND PARAGRAPH SPACING
============================================================

Provide a configurable line-height multiplier. The intended default is 1.4, meaning approximately 140% of the font's natural line height.

Also support:
- pixels_above: extra paragraph space above each paragraph/block;
- pixels_below: extra paragraph space below each paragraph/block;
- line_distance: optional additional vertical spacing, if retained.

Define the exact semantics of each setting in comments and user documentation. Do not let the same spacing be added twice through both line height and paragraph margins.

Important correction to the reference design:
The old code computes a pixel height from QFontMetrics(document()->defaultFont()).lineSpacing(), multiplies it by the configured multiplier, adds line_distance, then applies QTextBlockFormat::FixedHeight. This makes the block height fixed in pixels based on the document default font. It can become too small for taller fallback fonts or glyphs and can behave unexpectedly when fonts or font metrics change.

For the rewrite, prefer a proportional line-height model where technically appropriate:
- A multiplier of 1.4 maps to 140 percent.
- Evaluate QTextBlockFormat::ProportionalHeight (for example, 140.0) for proportional line spacing.
- Use MinimumHeight only if the intended semantics are a minimum line box rather than a proportional line height.
- Use fixed pixel height only if there is a clearly documented reason and it is proven not to clip glyphs or fallback fonts.

If an extra pixel-based line_distance option is kept, define how it combines with proportional height. If the combination cannot be implemented cleanly, either implement it as a separate paragraph spacing feature or deprecate it with a clear migration note. Do not silently ignore it.

Font changes must update the layout and line-number geometry. Pasted Unicode text, combining marks, emoji, and fallback-font glyphs must not be vertically clipped by an undersized fixed line height.

All existing paragraphs and newly created paragraphs must use the same configured metrics. The line-height setting must not change the actual plain-text content.

Configuration values must be validated and clamped to sensible ranges. Reject NaN/infinite values. Use one validation policy in both configuration parsing and editor setters.

8. LINE NUMBERS, CURRENT-LINE HIGHLIGHT, AND EDITOR LAYOUT
============================================================

A. Line numbers
- Implement a left-side line-number gutter.
- Number logical paragraphs/blocks, not visual wrapped rows.
- Recalculate gutter width when the document's logical line count crosses a digit boundary (9 to 10, 99 to 100, etc.).

- Repaint only the necessary region when practical, but correctness is more important than micro-optimization.
- Hiding line numbers must reclaim the gutter width cleanly without changing the document's text or line-height settings.
- Do not assume a wrapped paragraph occupies only one visual row when calculating drawing positions.

B. Current-line highlight
- Highlight the logical paragraph containing the cursor.
- Extend the highlight across the text viewport width.
- Use the configured current-line color if valid; otherwise derive a subtle color from the editor background.
- Update on cursor movement, selection changes, document changes, and relevant palette/configuration changes.
- Respect read-only state if one is introduced.

C. Viewport and margins
- Keep gutter geometry, viewport geometry, and editor borders synchronized on resize.
- Recalculate after font, line-number visibility, border, DPI, and window-size changes.
- Use logical Qt widget coordinates and avoid unnecessary hard-coded assumptions about physical pixels.
- The bottom inset must be intentional and independently configurable.
- Do not make the bottom gap appear only in maximized mode.
- Do not overlap the editor viewport with the status bar.
- Ensure the final visible line can be scrolled fully into view.
- Check vertical scrollbar maximum/range after pasting a large document.

D. Resizing and window states
The GUI must be correct in:
- normal/restored window;
- maximized window;
- full-screen mode;
- small supported window dimensions;
- high-DPI display scaling.

The editor must use the available central-widget geometry. Avoid fixed bottom spacers and geometry calculations that assume a maximized screen.

15. KNOWN DEFECTS IN THE REFERENCE IMPLEMENTATION THAT MUST NOT BE REPEATED
============================================================

1. Clipboard paste does not have a deliberate custom plain-text insertion path. Enter has special formatting code, but paste does not receive equivalent post-insertion formatting treatment.

2. The blockCountChanged handler is intentionally empty. Do not turn it into a synchronous formatting hook that breaks consecutive empty paragraphs. Format affected blocks at controlled editing-operation boundaries instead.

3. Enter inserts a QTextBlock manually and applies FixedHeight formatting. Do not assume this automatically makes paste, load, and all other insertion paths consistent.

4. FixedHeight line boxes are calculated from the document default font. This can be too small for fallback-font glyphs or changed font metrics. Prefer a well-defined proportional model or justify another strategy and test it.

5. Runtime EditorConfig defaults conflict with the default config text printed by main.cpp and partly conflict with the Editor constructor. Remove all duplicated/conflicting defaults.

6. ConfigManager accepts a wider line-height range than Editor actually uses. Unify validation and effective values.

7. MainWindow::openFiles() reads/loads paths in two loops. It can load documents more than once and discards all but one document because there are no tabs. Replace it with one clear path-handling implementation.

8. openFilesAndMaximize() opens supplied paths by repeatedly loading into the same Editor, so only the final successfully loaded file remains. Do not imply that multiple files are open simultaneously.

9. The desktop entry's Exec field in the reference points to /usr/bin/s3 even though the CMake executable is named slate. Fix the launcher to point to the actual installed binary.

10. Config reload replaces the KeyBindings object, but menu QActions were created earlier. Update action shortcuts when configuration reloads.

11. The editor uses the same border-size value for left, top, right, and bottom viewport margins. Separate the layout concepts and verify that bottom spacing is not mistaken for status-bar space.

12. The bottom-space symptom has not been proven to be a single defect. The reference uses setViewportMargins(left, border, border, border), and the no-config border default is 20 instead of the printed default of 8. Status-bar visibility defaults also differ. Rebuild the layout so the cause is explicit and test normal/maximized/full-screen states. Do not claim a particular visual root cause without reproducing it.
